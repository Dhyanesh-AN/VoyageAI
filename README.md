# Voyage AI

**A Multi-Agent Travel Planner powered by LangGraph**

Turn a single natural-language request into a complete, budget-aware travel plan — flights, hotels, weather, and a day-by-day itinerary — generated by a coordinated team of AI agents with built-in guardrails and human-in-the-loop approval.

## Overview

Planning a trip usually means bouncing between flight search engines, hotel sites, weather forecasts, and a half-finished budget spreadsheet. **Voyage AI** collapses that workflow into a single conversation.

Under the hood, a supervised graph of specialist agents researches, reasons about, and negotiates a coherent plan — checking it against the user's budget, adjusting the plan if it isn't feasible, and pausing for human approval before finalizing anything.

## Features

| | |
|---|---|
| 🛡️ **Input Guardrail** | Screens incoming requests to keep the system scoped to legitimate travel planning |
| 🧭 **Supervisor Routing** | An LLM planner decides which specialist agents a given request actually needs, and extracts structured trip constraints (destination, budget, dates, style) |
| ⚡ **Parallel Agent Execution** | Flight, hotel, and weather research run concurrently rather than one after another, cutting end-to-end latency |
| 💰 **Budget-Aware Planning** | A dedicated budget agent estimates cost and risk before the itinerary is drafted |
| 🔁 **Dynamic Replanning** | If the budget risk comes back high, the system automatically adjusts trip constraints (shorter stay, cheaper style) and re-checks feasibility — no user intervention needed |
| 🤝 **Agent Negotiation** | The budget agent and itinerary agent go back and forth on the draft plan (bounded rounds) until it's realistically affordable |
| 🧑‍⚖️ **Human-in-the-Loop Approval** | The draft itinerary pauses for explicit user approval or revision feedback before a final plan is generated |
| 🧱 **Structured Outputs** | Guardrail, routing, budget, and negotiation decisions use schema-validated (Pydantic) LLM outputs instead of ad-hoc text parsing |
| ✈️ **Flight Research** | Flight and airport data via the AviationStack MCP integration |
| 🏨 **Hotel Discovery** | Accommodation research via the Tavily MCP integration |
| 🌦️ **Live Weather & Forecast** | Current conditions and forecasts via a custom OpenWeather MCP server |
| 💾 **Durable, Resumable Sessions** | Conversation and workflow state persisted to PostgreSQL via LangGraph's checkpointer, so an in-progress plan survives a restart |
| 🌐 **Web Interface** | FastAPI backend with a lightweight built-in frontend |

## How the Workflow Works

```text
                         User Request
                              │
                              ▼
                        🛡️  Guardrail
                    (blocks off-topic/unsafe requests)
                              │
                              ▼
                      🧭  Supervisor Agent
              (decides which agents are needed,
               extracts structured trip constraints)
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        ✈️ Flight Agent  🏨 Hotel Agent  🌦️ Weather Agent      (run in parallel)
              └───────────────┼───────────────┘
                              ▼
                     💰  Budget Agent
                              │
                 high risk ───┴─── low/medium risk
                    │                    │
                    ▼                    │
              🔁 Replan Agent            │
           (adjusts constraints,         │
            re-checks with Budget)       │
                    └────────────────────┘
                              ▼
                    🗓️  Itinerary Agent
                              │
                              ▼
                  🤝  Budget Review Agent
                              │
              not feasible ───┴─── feasible / round limit reached
                    │                    │
                    └── revise ──────────┘
                              ▼
                  🧑‍⚖️  Human Approval
                   (approve or request changes)
                              │
                              ▼
                    🧩  Final Response Agent
                              │
                              ▼
                       Final Travel Plan
```

1. The **guardrail** checks that the request is a legitimate travel-planning ask.
2. The **supervisor** decides which specialist agents are relevant and extracts structured trip constraints from the request.
3. **Flight, hotel, and weather agents** run concurrently — none of them depend on each other's output.
4. The **budget agent** estimates cost and flags a risk level. If risk is high, a **replan agent** adjusts the trip constraints (e.g. a shorter stay) and the budget check re-runs once.
5. The **itinerary agent** drafts a full plan, and the **budget review agent** checks it for feasibility — looping back for a revision if needed, up to a fixed number of rounds.
6. The draft pauses for **human approval**; the user can approve it or send back feedback for another revision.
7. The **final response agent** assembles the approved plan into a polished, formatted answer.

## Tech Stack

- **Language:** Python 3.10+
- **Backend:** FastAPI
- **Frontend:** Jinja2 + HTML/CSS/JavaScript
- **Orchestration:** LangGraph (parallel fan-out/fan-in, conditional loops, human-in-the-loop interrupts) + LangChain
- **LLM Provider:** Groq
- **Structured Outputs:** Pydantic schemas via `with_structured_output`
- **State Persistence:** PostgreSQL (`langgraph-checkpoint-postgres`)
- **Tool Integration:** Model Context Protocol (MCP) — Tavily (hosted), AviationStack (via `uvx`), and a custom local OpenWeather MCP server

## Prerequisites

Before running Voyage AI locally, make sure you have:

- Python **3.10+**
- **PostgreSQL** running and accessible (used for workflow state/checkpointing)
- **[uv](https://docs.astral.sh/uv/)** installed, so the `uvx` command is available (used to run the AviationStack MCP server)
- API keys for:
  - **Groq**
  - **Tavily**
  - **AviationStack**
  - **OpenWeather**

## Environment Variables

Create a `.env` file in the project root:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/travel_db
GROQ_API_KEY=your_groq_api_key
AVIATION_STACK_API_KEY=your_aviationstack_api_key
TAVILY_API_KEY=your_tavily_api_key
OPENWEATHER_API_KEY=your_openweather_api_key
```

> `AVIATIONSTACK_API_KEY` is also accepted as an alias for `AVIATION_STACK_API_KEY`.

## API Endpoints

> Adjust these to match the exact routes defined in `app.py` — the table below reflects the two operations the backend workflow supports: starting a plan and resuming it after human review.

| Method | Endpoint | Description |
|--------|-----------|-------------|
| `GET`  | `/health` | Health check |
| `POST` | `/api/travel` | Submit a new travel request and run the workflow up to the human-approval step |
| `POST` | `/api/travel/resume` | Resume a paused plan with an approval decision and optional revision feedback |

**Example: start a plan**

```bash
curl -X POST http://127.0.0.1:8000/api/travel \
  -H "Content-Type: application/json" \
  -d '{"message":"Plan a 5-day trip to Tokyo with a budget of $1200"}'
```

**Example: approve or revise the draft itinerary**

```bash
curl -X POST http://127.0.0.1:8000/api/travel/resume \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"user_abc123","approved":false,"feedback":"Make day 3 less packed"}'
```
